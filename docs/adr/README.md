# Architecture Decision Records

Short, dated, immutable records of significant technical decisions and *why* they
were made. When a decision changes, we don't edit history — we add a new ADR that
supersedes the old one.

## Format

Each ADR: **Context** (the forces at play) → **Decision** (what we chose) →
**Consequences** (what follows, good and bad) → **Alternatives considered**.
Keep them terse. The goal is that someone joining the project cold can read the
ADRs in order and understand how we got here.
